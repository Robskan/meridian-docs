Every **command flow** begins with a Command block. It defines how users invoke the flow in Discord and what metadata Discord shows in autocomplete.

## What it does

Listens for a slash command, prefix command, or context menu action and starts the connected blocks. The Command block is the root of the canvas: you cannot delete it or add another from the palette.

## Common uses

<CardGroup cols={2}>
  <Card title="Slash commands" icon="slash">
    Register `/ping` style commands with Discord descriptions and options.
  </Card>

  <Card title="Prefix commands" icon="hashtag">
    Run flows when someone types `!help` or your configured prefix.
  </Card>

  <Card title="Context menus" icon="mouse-pointer">
    Right-click a user or message to run a flow from the apps menu.
  </Card>
</CardGroup>

<Note>
  This block is placed automatically by the builder. You cannot add it from the block palette.
</Note>

## Configuration

Open the block in the builder sidebar to configure these fields.

<ParamField path="trigger_type" type="string" required>
  How users start this flow.

  Options: `slash`, `prefix`, `user`, `message`.
</ParamField>

<ParamField path="friendly_name" type="string" required>
  Title on the canvas card and in your command list.
</ParamField>

<ParamField path="discord_name" type="string">
  Slash command name Discord registers. Lowercase, no spaces.
</ParamField>

<ParamField path="discord_description" type="string">
  Shown in Discord slash command autocomplete.
</ParamField>

<ParamField path="prefix_command_name" type="string">
  Word after your prefix (for example `ping` in `!ping`).
</ParamField>

<ParamField path="prefix_command_aliases" type="list">
  Up to five alternate prefix names that run the same flow.
</ParamField>

<ParamField path="safe_test_mode" type="boolean">
  Skips destructive steps (moderation, API calls, Ask AI, persisted variables) and posts a short notice instead.
</ParamField>

## Example workflow

<Steps>
  <Step title="Pick a trigger type">
    Slash is the default for new commands. Use prefix if your server relies on a text prefix.
  </Step>
  <Step title="Name the command">
    Set a friendly name for your dashboard, then the Discord-facing name and description.
  </Step>
  <Step title="Add options (slash only)">
    Attach Command option blocks under the Command node for typed parameters.
  </Step>
  <Step title="Connect actions">
    Draw a connection from the bottom handle to your first action block.
  </Step>
</Steps>

<Tip>
  Enable **Test mode** while building flows that touch roles, channels, or external APIs so you can run them safely in a live server.
</Tip>
