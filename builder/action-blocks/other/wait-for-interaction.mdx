Wait for interaction pauses the flow until a user reacts, sends a message, or uses a component.

## What it does

Holds execution open for up to 30 seconds (Free/Hobby) or 60 seconds (Pro/Max), then continues on the next block. Saves user, message, or content to variables.







## Configuration

Open the block in the builder sidebar to configure these fields.

<ParamField path="interaction_types" type="string" required>
  What counts as a valid response.

Options: `reaction`, `message`, `button`, `select_menu`, `modal_submit`.
</ParamField>

<ParamField path="user_filter" type="string">
  Restrict who can continue the flow.
</ParamField>

<ParamField path="timeout_seconds" type="number">
  Max wait time.
</ParamField>

<ParamField path="save_user_var" type="string">
  Stores responder user id.
</ParamField>

<ParamField path="save_message_var" type="string">
  Stores message id.
</ParamField>

<ParamField path="save_content_var" type="string">
  Stores message text or emoji.
</ParamField>

## Example workflow

<Steps>
  <Step title="Send a message with buttons">
    Add buttons in Send a Message, then place Wait for interaction below.
  </Step>
  <Step title="Filter who can click">
    Limit to command user or a role for games and confirmations.
  </Step>
  <Step title="Handle timeout">
    Follow with an If block checking whether variables were set.
  </Step>
</Steps>
